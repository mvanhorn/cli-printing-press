## Part A - Install `pp` and wire your agents (zero Go required)

1. Install `pp` to `~/.local/bin/pp`:

   ```bash
   curl -fsSL https://raw.githubusercontent.com/mvanhorn/cli-printing-press/main/scripts/install-pp.sh | sh
   ```

   Ensure `~/.local/bin` is on `PATH`, then verify:

   ```bash
   pp --version
   ```

2. Wire the single 5-tool local MCP server (`pp mcp`), Ardia plugin (if installed), and routing skill automatically:

   ```bash
   pp setup --apply
   ```

   This single stdio server exposes 5 progressive-discovery tools (`pp_route`, `pp_discover`, `pp_run`, `pp_lake_search`, `pp_lake_sql`) plus MCP `initialize` instructions so deferred-tool hosts like Claude Code auto-discover `pp_run` across all 616+ apps and your local Life Lake.

   Manual config equivalent (for Claude Desktop, Cowork, Windsurf, or custom hosts):

   ```json
   {
     "mcpServers": {
       "printing-press": {
         "command": "pp",
         "args": ["mcp"]
       }
     }
   }
   ```

3. Match your existing Ardia, Chrome, or Firefox domains against the 616+ supported apps (reads plaintext hostnames only, zero Keychain popups):

   ```bash
   pp onboard
   ```

4. Smoke-test a starter cartridge (~150ms, compact JSON, no browser tab) and seed your local Personal Life Lake (`~/.pp/lake.db`):

   ```bash
   pp route https://www.espn.com/nba/scoreboard --json
   pp run espn scoreboard --compact --limit 5 --json
   pp lake sync espn hackernews
   pp audit --json
   ```

## Part B - Logged-In Browser Sessions (Ardia + Google Chrome)

- Ardia Browser: `pp auth sync <app> --browser ardia` syncs strictly one domain's cookies into encrypted `~/.press-auth/<domain>.json` (cached 24h and checked against JWT expiry so repeat calls stay ~1ms).
- Google Chrome (via OpenCode `browse`): pass `--via browse` (CLI) or `via_browse: true` (MCP `pp_run`) to run HTTP/GraphQL Cartridges inside Chrome using `credentials: "include"` (attaches real HttpOnly cookies with zero Keychain prompts, enforces `trust.allowed_hosts`, and chunks >100 KB responses cleanly).
- 1Password Touch ID: configure `op_ref: op://Vault/Item/field` (or an env var starting with `op://`) for zero plaintext API tokens on disk.

## Part C - Standing Agent Routing Rule ("Skip Pixels on Repeat Work")

Save these rules in your agent's persistent instructions:

1. Before opening a browser tab (`ardia browse`, `browse`, or computer-use) for a known consumer site, SaaS app, or repeat lookup, check the fast path first:
   `pp route <url-or-app> --json`
2. If `matched: true`, call `pp run <app> <cmd> --compact --json` (or MCP `pp_run`). All 616+ library binaries auto-hydrate (SHA-256 verified, zero Go) on first call and run in ~150ms thereafter. Pass `--via browse` / `via_browse: true` when a Cartridge needs Chrome's logged-in cookies.
3. For multiple `route`, Cartridge `run`, or Life Lake (`lake_search`/`lake_sql`) operations in one turn, use `pp batch '[...]'` (for prebuilt library binaries such as `digg` or `instacart`, invoke `pp run <app> ...` directly).
4. If `matched: false` and the user will repeat this workflow, compile it once from a real browser session:
   `pp record --backend auto <url>` (Ardia first, then Chrome via OpenCode `browse`) or `pp record --from-har <capture.har>`.
   Every subsequent run skips the browser forever.
5. For cross-app personal questions, query the local Life Lake first:
   `pp lake search "<query>" --json` or `pp lake sql "SELECT ..."` (read-only, ~5ms, zero cloud).
6. If a previously working cartridge fails with HTTP 404/410 or schema extraction drift, run `pp heal <app> <cmd>` instead of falling back to brittle pixel clicking.
